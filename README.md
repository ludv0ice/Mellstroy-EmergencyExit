# АРМ марафона по бегу — этап 1

Курсовой проект Ченцова Руслана Игоревича. Сейчас реализованы ORM-модели SQLAlchemy и миграция PostgreSQL. FastAPI содержит только объект приложения; маршруты и авторизация — следующие этапы.

## Запуск

Нужны Python 3.10+ и PostgreSQL 16 (либо Docker Compose).

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
docker compose up -d --wait db
alembic upgrade head
alembic check
python -m scripts.seed
uvicorn app.main:app --reload
```

Если PostgreSQL уже установлен, вместо Docker создайте пустую БД и задайте подключение. По умолчанию используется `postgresql+psycopg://marathon:marathon_local@localhost:5432/marathon`.

```bash
# Linux/macOS:
export DATABASE_URL='postgresql+psycopg://user:password@localhost:5432/marathon'
# PowerShell:
# $env:DATABASE_URL='postgresql+psycopg://user:password@localhost:5432/marathon'
```

Пароль `marathon_local` в Compose предназначен только для локальной учебной БД. При его изменении задайте соответствующий DATABASE_URL. Swagger: http://127.0.0.1:8000/docs (предметных маршрутов пока нет).

### Ошибка установки psycopg-binary

Старая версия `3.2.6` не имеет подходящего пакета для некоторых версий Python/платформ. Драйвер обновлен до диапазона `psycopg[binary]>=3.3.6,<3.4`. Установите зависимости заново приведенной выше командой. Старый `requirements.lock.txt` удален: он фиксировал лишние библиотеки и несовместимый драйвер. При иной ошибке проверьте версию Python, архитектуру и используемый индекс пакетов.

## Файлы

- `app/models/` — 16 моделей, каждая в отдельном файле согласно методическим рекомендациям.
- `app/database.py` — Base и создание подключения; `app/main.py` — основа FastAPI.
- `migrations/`, `alembic.ini` — начальная миграция и конфигурация Alembic.
- `scripts/seed.py` — заполнение пустой учебной БД.
- `tests/`, `pytest.ini` — интеграционные проверки PostgreSQL.
- `compose.yaml` — локальная PostgreSQL.
- `docs/erd.md`, `docs/data_dictionary.md` — ER-диаграмма и словарь данных.
- `requirements.txt` — 5 прямых зависимостей приложения; `requirements-dev.txt` добавляет только pytest.

## Тестовые данные и проверки

Заполнение синтетическими данными запускается отдельно, одной транзакцией. Во всех предметных таблицах не менее 50 записей; справочники ролей и дистанций содержат по 3 записи. Учетные записи отключены; рабочих паролей нет. Повторное заполнение непустой БД запрещено.

Для тестов создайте **отдельную пустую БД**:

```bash
python -m pip install -r requirements-dev.txt
docker compose exec db createdb -U marathon marathon_test
# Linux/macOS:
export TEST_DATABASE_URL='postgresql+psycopg://marathon:marathon_local@localhost:5432/marathon_test'
# PowerShell:
# $env:TEST_DATABASE_URL='postgresql+psycopg://marathon:marathon_local@localhost:5432/marathon_test'
python -m pytest -q
```

Тесты проверяют миграцию, соответствие моделям, наполнение, связи и ограничения. После проверки удаляют созданные таблицы тестовой БД; с непустой БД работать отказываются. `alembic downgrade base` удаляет таблицы и данные выбранной DATABASE_URL — применяйте только если нужен полный откат.

## Принятые решения
Регистрация связывает бегуна с конкретным забегом, забег — дистанцию с ежегодным мероприятием. Бегун может участвовать в нескольких забегах; повторная регистрация на тот же забег запрещена. Спонсорство относится к регистрации, поэтому условия и сумма сохраняются отдельно для каждого участия. Номер участника уникален в пределах забега. Результат и сертификат имеют связь один-к-одному с регистрацией. Числовое время хранится в секундах; место в рейтинге вычисляется сортировкой результатов finished внутри забега по времени, при равном времени участники делят место (SQL RANK), dns/dnf/dsq исключаются. Сам рейтинг не дублируется в профиле бегуна.

Связь пользователей и ролей многие-ко-многим реализована через user_roles. Роль coordinator предусмотрена для подтверждения соглашений, но проверка прав будет добавлена на этапе авторизации. Суммы хранятся как NUMERIC(12,2), не float. Даты стартов и действий имеют часовой пояс; тексты поддерживают Unicode. Язык новостей хранится явно; локализация интерфейса — следующий этап.

В БД обеспечены PK/FK/UNIQUE/NOT NULL/CHECK, запрет отрицательных сумм, недопустимых дистанций, времени и смен, согласованность полей подтверждения спонсорства. Удаление предметных данных по FK запрещено RESTRICT для сохранения истории; удаление пользователя каскадно удаляет только назначения ролей. Основные бизнес-сущности удаляются явно с учетом зависимостей.

Межтабличные правила (лимит мест, дата рождения до забега, роль подтверждающего координатора, выдача finish-сертификата только после результата finished, допустимые переходы статусов и пересечение смен волонтеров) требуют транзакционного сервисного слоя последующих этапов. На этом этапе они не объявляются реализованными. Документы представлены ссылками, загрузка файлов пока не реализована. Схема приведена к 3НФ: справочники отделены, связи многие-ко-многим раскрыты, вычисляемые рейтинги не хранятся.
