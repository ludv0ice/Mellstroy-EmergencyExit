# Как устроен код

Игра использует обычные JavaScript-модули без дополнительного фреймворка интерфейса. Ресурсы лежат в `assets/`, исходники — в `src/`, запуск — через корневой `index.html`.

## От запуска до кадра игры

1. `main.js` загружает ресурсы, создаёт Phaser и хранит текущее состояние приложения в объекте `app`.
2. При входе на этаж метод `app.load()` создаёт `Simulation` и передаёт её в `GameView`.
3. `levels.js` подготавливает объекты комнаты и рисует её пол, стены и переходы.
4. `renderer.js` читает клавиатуру и мышь, передаёт действия в `sim.update()` и рисует состояние мира.
5. `simulation.js` обновляет движение, оружие, врагов, пули и выход. События смерти и завершения этажа возвращаются в `app.onEvent()`.
6. `ui.js` обновляет надписи HUD и обрабатывает кнопки. Переходы между экранами остаются в `main.js`.

| Изменение | Файл |

| Движение и столкновения | `src/simulation.js`: `updatePlayer()`, `move()`, `canMoveTo()` |
| Стрельба и ближний удар | `src/simulation.js`: `shoot()`, `meleeAttack()` |
| Подбор, сброс и бросок | `src/simulation.js`: `pickup()`, `dropWeapon()`, `throwWeapon()` |
| Создание оружия на полу | `src/simulation.js`: `dropItem()` |

| Кнопки, HUD и сенсорное управление | `src/ui.js` |

## Настройки оружия

В `definitions` у каждого оружия есть `name` и `sprite`. У огнестрельного также заданы именованные поля `ammo`, `cooldown`, `pellets`, `spread`, `sound`. Их порядок внутри объекта не важен.

Время задаётся в секундах: например, `10 / 60` — десять кадров при 60 FPS. Угол разброса переводится из градусов в радианы через `Math.PI / 180`.

В таблице `melee` поле `reach` задаёт базовую длину удара, а `cooldown` — задержку. Дальность героя рассчитывается как `reach * 1.2`, врага — как `reach * 0.7`. `sharpWeapons` перечисляет острые виды оружия, `silentGuns` — оружие с глушителем.

Порядок записей в `definitions` сохраняйте: их номера используются в картах и сохранённом состоянии этажа.

## Как читать файлы

В исходниках используются обычные функции, классы, массивы, объекты, циклы и условия с фигурными скобками. Настройки глав, уроков, оружия и анимаций записаны именованными полями. В `simulation.js` сначала создаётся мир, затем `update()` вызывает действия по порядку. Поиск столкновения пули находится в `findBulletHit()`, создание врага — в `createEnemy()`.

`renderer.js` рисует мир через Canvas. `drawEnemy()` и `drawPlayer()` отвечают за персонажей. `physics.js` содержит геометрические расчёты и поиск пути по клеткам; они нужны для столкновений и обхода стен. Формулы сохранены, чтобы поведение игры осталось прежним.

В `tools/level-data.mjs` каждая карта содержит `id`, `title`, `theme`, `zones` и `landmark`. В каждой зоне явно указаны координаты, размеры, название, стиль пола и мебель. `node tools/create-levels.mjs` превращает эту таблицу в готовые карты.

## Сборка

После правок выполните `npm test`, `npm run build`, `npm run check:assets`. Node.js нужен для разработки; готовая игра запускается без него.

`assets/game.js` и `assets/data.js` создаются сборкой. Для правок используйте исходные модули и JSON. Сборка готовит их для запуска через обычный `index.html`, включая открытие без сервера. Для размещения на сайте используются те же `index.html`, `assets/` и `src/style.css`.
